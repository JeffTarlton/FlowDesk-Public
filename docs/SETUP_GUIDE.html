Before you start

5 minutes · read this once

What you are building

FlowDesk is an app you use in your web browser. It has two parts:

  • The database, which holds your tickets, users, comments and files, and handles signing in. It always lives in Supabase, a free online service. Both setup paths use it.
  • The FlowDesk app, the screens you click around in. You choose where it runs: online, or on your own computer.

Choose how you'll run FlowDesk

Pick the path that fits you. The guide then shows only the steps for that path. You can change your choice at any time with the switcher at the top of the contents list.

Not sure yet? , or start with On my computer. You can move to online later without losing anything, because both paths use the same Supabase database.

What you need

  • A computer (Windows or Mac) with Chrome, Edge, Firefox or Safari. A phone or tablet is not enough for setup.
  • An email address you can open right now (for confirmation codes).
  • A safe place to save passwords and a few values: a password manager, or at least a private text note. You will be told exactly what to save.
  • On my computer Permission to install free software on this computer (Node.js).

Tips that prevent most mistakes

  • Keep this guide open in its own tab. Links in this guide open in a new tab, so you won't lose your place.
  • Words in a shaded box are buttons, links or menu items to click on screen.
  • A path like Authentication›Sign In / Providers means: click Authentication, then click Sign In / Providers.
  • Green "You should see" boxes tell you what success looks like. If you don't see it, stop and check the step again, or go to Troubleshooting.
  • Websites change their look from time to time. If a button has moved or been renamed slightly, look for the same words nearby.
  • Tick "I've finished this step" at the end of each step. Your progress is saved in this browser.

1

GitHub: create an account and get your own copy of the code

10 minutes · github.com
Online path

What is GitHub? A website that stores code. The FlowDesk code lives there. You will make your own copy of it (called a fork). Vercel will build your website from your copy in step 7.

1.1 Create a free GitHub account

Already have one? Sign in and skip to 1.2.

  1. Open github.com/signup.
  2. Enter your email, create a password, and choose a username (letters, numbers and single hyphens, for example janesmith). Write the username in the worksheet.
  3. Click Continue / Create account and complete the "verify you're human" puzzle if one appears.
  4. GitHub emails you a code. Open your email, copy the code and type it into GitHub.
  5. If GitHub asks questions about you or your team, you can answer them or click Skip personalization. Choose the Free plan if asked.
You should seeYour GitHub home page (the "Dashboard"), with your profile picture in the top-right corner.

1.2 Fork the FlowDesk repository (make your own copy)

A repository ("repo") is a project folder on GitHub. Forking copies it into your account.

  1. While signed in, open github.com/JeffTarlton/FlowDesk-Public.
  2. Near the top-right of the page, click Fork (it has an icon like a branching "Y").
  3. On the Create a new fork page:
    • Owner: your username (already selected).
    • Repository name: leave it as FlowDesk-Public.
    • Leave Copy the main branch only ticked.
  4. Click Create fork and wait a few seconds.
You should seeA page whose address is https://github.com/YOUR-USERNAME/FlowDesk-Public, with the words "forked from JeffTarlton/FlowDesk-Public" under the name. This is your copy. From now on, "your fork" means this page.

1.3 Optional: download the code to your computer

You don't need to download anything for this guide. In steps 3 and 4 you will copy files directly from your fork on GitHub. If you'd like a copy on your computer anyway:

  1. On your fork's page, click the green <> Code button.
  2. Click Download ZIP.
  3. Find the downloaded FlowDesk-Public-main.zip (usually in your Downloads folder). On Windows, right-click it and choose Extract All…. On a Mac, double-click it.
Want a copy running on your own computer as well, or to use the command line? See Appendix A after you finish the main steps. It isn't needed to get your website live.

How to find a file in your fork

You will need this in steps 3 and 4. Files are organised in folders, just like on your computer:

  1. On your fork's main page, you'll see a list of folders and files. Click a folder name (for example supabase) to open it.
  2. Keep clicking folder names until you reach the file, then click the file name to open it.
  3. To copy a whole file, click the Copy raw file button above the file's contents, on the right. It looks like two overlapping squares ⧉. A small "Copied!" message confirms it.

Supabase: create an account and a project

5 minutes · supabase.com

What is Supabase? The service that stores FlowDesk's data and handles signing in. A project is one database with everything around it. You'll create one project for FlowDesk.

2.1 Create a free Supabase account

  1. Open supabase.com/dashboard/sign-up.
  2. Click Continue with GitHub. This is the easiest option because you're already signed in to GitHub.
  3. GitHub asks whether to let Supabase use your account. Click Authorize supabase.

On my computer No GitHub account? Sign up with your email and a password on the same page instead. Supabase emails you a confirmation link: open it, then sign in.

2.2 Create an organization (first time only)

Supabase may ask you to create an organization first. It is just a folder for your projects.

  1. Name: anything, for example your company name or your own name.
  2. Type: Personal is fine.
  3. Plan: Free - $0/month.
  4. Click Create organization.

2.3 Create the project

  1. If the new-project form isn't already open, click New project (or open database.new).
  2. Fill in the form:
    FieldWhat to enter
    OrganizationThe one you just created.
    Project nameflowdesk (or anything you like).
    Database passwordClick Generate a password, then copy it and save it in your password manager now. You won't normally need it, but you can't view it again later.
    RegionThe location closest to the people who will use FlowDesk. This can't be changed later.
    Anything else (security, Data API, advanced options)Leave the defaults. FlowDesk needs the Data API switched on, which is the default. An option to automatically expose new tables can stay unticked: FlowDesk grants access to its own tables itself.
  3. Click Create new project.
  4. Wait one or two minutes while Supabase sets it up. Don't close the tab.
You should seeYour project's home page, with a menu down the left side (Table Editor, SQL Editor, Authentication, Edge Functions and so on).

2.4 Find your project ref

Every Supabase project has a project ref: a random-looking ID of 20 lowercase letters and numbers. You'll use it several times.

  1. Look at your browser's address bar. It shows something like supabase.com/dashboard/project/abcdefghijklmnopqrst.
  2. The part after /project/ is your project ref. (It is also shown as Project ID under Project Settings›General.)
  3. Copy the whole address and paste it into the worksheet. The ref is picked out automatically.
Free projects go to sleep Supabase pauses free projects after about one week with no activity. When that happens, FlowDesk looks broken (pages stay empty or sign-in fails). The fix: open the Supabase dashboard and click Resume project (or Restore). Regular use keeps it awake.

3

Build the database: run the two scripts

5 minutes · in the Supabase dashboard

FlowDesk's database is described in two script files (SQL files) that come with the code. You'll paste each one into Supabase's SQL Editor and click Run. Order matters: script 1 first, then script 2.

On my computer The instructions below copy the files from GitHub, which works without an account. If you prefer, open the same files from your downloaded folder instead (supabase › migrations) in Visual Studio Code or Notepad, select everything and copy it.

OrderFile (folder supabase/migrations/)What it does
120260926000000_flowdesk_schema.sqlCreates all of FlowDesk's tables, security rules, file storage and default settings. Long file (about 1,900 lines).
220260926000100_seed_admin.sqlCreates the first account you'll sign in with: admin@flowdesk.com.

3.1 Run script 1: the schema

  1. In a new tab, open the code on GitHub (your forkthe FlowDesk repository), then open the folder supabase, then migrations, then click 20260926000000_flowdesk_schema.sql.
    Open script 1 on GitHub
  2. Click the Copy raw file button ⧉ (top-right of the file contents). You've now copied the whole file.
    Can't find it? Click Raw instead, press Ctrl+A (Mac: ⌘+A) to select everything, then Ctrl+C (Mac: ⌘+C) to copy.
  3. Go back to your Supabase project. In the left menu, click SQL Editor. Start a new, empty query with the + / New query button.
    Open a new SQL query
  4. Click inside the empty editor and paste: Ctrl+V (Mac: ⌘+V).
  5. Click once in the editor so no text is highlighted. (If some text is highlighted, only that part runs.)
  6. Click Run (bottom-right), or press Ctrl+Enter (Mac: ⌘+Enter).
  7. If a pop-up warns that the query has "destructive operations", confirm and run it anyway. That's expected: the script replaces its own settings so it can safely be run again. It does not delete any data.
You should seeSuccess. No rows returned in the results panel under the editor, after a few seconds.

3.2 Run script 2: the admin account

  1. On GitHub, go back to the supabase/migrations folder and open 20260926000100_seed_admin.sql. Click Copy raw file ⧉.
    Open script 2 on GitHub
  2. In Supabase's SQL Editor, start another new query (+ / New query). Don't paste it after script 1.
  3. Paste, make sure nothing is highlighted, and click Run.
You should seeA success message (for example Success. No rows returned).

3.3 Check that it worked

Start one more new query, paste the line below, and click Run:

select email, role, is_active, force_password_reset from public.profiles;
You should seeExactly one row: admin@flowdesk.com · admin · true · true.
Made a mistake? Just run it again Both scripts are safe to run more than once. If script 1 showed an error, make sure you copied the whole file (it's long) into a fresh, empty query, and run it again. Then run script 2. If you ran script 2 first, simply run script 1 and then script 2 again.

4

Deploy the admin-actions Edge Function

5 minutes · in the Supabase dashboard · required

What is this? A small piece of code that runs inside Supabase and does the few jobs the website isn't allowed to do on its own, like creating user accounts and changing passwords. Without it, nobody can finish signing in for the first time, including you.

4.1 Copy the function code

  1. On GitHub (or in your downloaded folder), open the folder supabase, then functions, then admin-actions, then click index.ts.
    Open index.ts on GitHub
  2. Click Copy raw file ⧉.

4.2 Create the function in Supabase

  1. In your Supabase project's left menu, click Edge Functions.
    Open Edge Functions
  2. Click Deploy a new function, then choose Via Editor.
  3. The editor opens with some example code. Click inside it, select everything with Ctrl+A (Mac: ⌘+A) and press Delete, so the editor is completely empty.
  4. Paste the code you copied: Ctrl+V (Mac: ⌘+V).
  5. Find the function name box (next to the deploy button). Delete whatever name is there and type exactly: 
    admin-actions
    All lowercase, with a hyphen, no spaces. The name can't be changed later, so double-check it.
  6. Click Deploy function and wait for the success message.

4.3 Turn off "Verify JWT" (important)

The function checks who is calling it by itself, so Supabase's built-in check must be switched off. If it stays on, it can block real users.

  1. Open your new admin-actions function (click its name in the Edge Functions list) and go to its Details tab.
  2. Under Function configuration, turn OFF the switch called Verify JWT with legacy secret (it may just say Enforce JWT Verification or Verify JWT).
  3. Click Save changes.

4.4 Check that it works

Open this address in a new browser tab:

https://YOUR-PROJECT-REF.supabase.co/functions/v1/admin-actions

Open the check addressFill in your project ref in the worksheet to get a clickable link here.

The page showsWhat it means
{"error":"Method not allowed"}Perfect. The function is deployed and set up correctly. (Yes, an "error" is the good result here.)
A message such as Missing authorization header or Invalid JWTDeployed, but "Verify JWT" is still on. Repeat 4.3.
"Not found" or "Requested function was not found"Not deployed, or deployed with a different name. Repeat 4.2 with the exact name admin-actions, then delete the wrongly named function.

Turn off public sign-ups

1 minute · in the Supabase dashboard

In FlowDesk, only an admin creates accounts. Supabase allows strangers to sign up by default, so switch that off. Creating users from inside FlowDesk keeps working.

  1. In your Supabase project's left menu, go to Authentication›Sign In / Providers.
    Open Sign In / Providers
  2. Find Allow new users to sign up and turn it OFF.
  3. Click Save changes.
Only turn off "Allow new users to sign up". Leave the Email provider itself switched on, or nobody can sign in.

6

Copy your two Supabase values

2 minutes · in the Supabase dashboard

FlowDesk needs two values so it knows which Supabase project to talk to. In the next step you'll paste them into Vercelinto a small settings file on your computer.

Value 1: the Project URL

It's your project ref inside a web address:

https://YOUR-PROJECT-REF.supabase.co

If you filled in the worksheet, the box above already shows your real Project URL. You can double-check it with the Connect button at the top of your project (or under Integrations›Data API).

Value 2: the publishable key

  1. In the left menu, open Project Settings (the gear icon at the bottom), then API Keys.
    Open API Keys
  2. Find the Publishable key. It starts with sb_publishable_. Click its copy button.
  3. Paste it into your private note for a moment. It's not a secret, but you'll need it in step 7.

Only see "anon" and "service_role" keys? Your project uses the older key style. Use the anon (public) key instead, a long value starting with eyJ. It works the same way.

Never use the secret key On the same page there is a secret key (sb_secret_…) and possibly a service_role key. Never copy either of those into Vercel, into .env.local, or anywhere else in FlowDesk. Anything you give the website can be read by everyone who visits it, and a secret key would give them full control of your database.

Vercel: create an account and deploy the website

10 minutes · vercel.com
Online path

What is Vercel? A service that takes the code in your GitHub fork, builds it into a website and puts it online at a web address. Every time your fork changes, Vercel rebuilds the site automatically.

7.1 Create a free Vercel account

  1. Open vercel.com/signup.
  2. Choose Hobby ("I'm working on personal projects"). It's free. Enter your name if asked and click Continue.
  3. Click Continue with GitHub, then click Authorize Vercel on the GitHub page that opens.
The Hobby plan is for personal and non-commercial use. If you run FlowDesk for a business, check Vercel's pricing.

7.2 Import your fork

  1. Open vercel.com/new (or click Add New… › Project).
  2. Under Import Git Repository, find FlowDesk-Public and click Import next to it.
  3. Don't see it? Click Install or Adjust GitHub App Permissions. On the GitHub page that opens, choose Only select repositories, pick FlowDesk-Public, and click Install / Save. You're sent back to Vercel, where it now appears. Click Import.
You're now on the Configure Project page. Don't click Deploy yet. First do 7.3 and 7.4.
Vercel says "Project created… then deploy", but there's no settings form? Newer versions of Vercel's import screen create the project straight away and put the Deploy button below a list of recommended integrations. Scroll down, and set the environment variables (7.4) before you click Deploy. If you can't find a Deploy button at all, use the dashboard route in 7.5 instead. Your project already exists, so don't import it a second time.

7.3 Check the build settings (normally nothing to change)

SettingShould be
Project NameAnything lowercase, for example flowdesk. It becomes part of your web address.
Framework PresetVite
Root Directory./
Build and Output SettingsLeave as is: build command npm run build, output directory dist.

7.4 Add the environment variables

Environment variables are settings you give the website when it's built. FlowDesk needs exactly two. Open the Environment Variables section on the same page and add these, one at a time. Type the Key (name) exactly as shown, paste the Value, then click Add:

Key (copy exactly)Value
VITE_SUPABASE_URLYour Project URL from step 6: https://YOUR-PROJECT-REF.supabase.co
VITE_SUPABASE_ANON_KEYYour publishable key from step 6 (sb_publishable_…, or the older eyJ… anon key)

Copy-friendly versions of the two names:

VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
Common mistakes to avoid
  • No quotation marks and no spaces, before or after the value.
  • No slash at the end of the URL (.supabase.co, not .supabase.co/).
  • The key name is VITE_SUPABASE_ANON_KEY even if you use the new publishable key. That's correct.
  • If Vercel shows environment checkboxes, keep Production and Preview ticked.

7.5 Deploy

  1. Click Deploy.
  2. Wait one to three minutes while Vercel builds the site. Yellow warnings in the build log (for example about "large chunks") are normal and harmless.
  3. When you see Congratulations (or a screenshot of the site), click Continue to Dashboard.
  4. On the project page, find Domains. The short address listed there (for example https://your-project.vercel.app) is your website. Write it in the worksheet.
    Vercel also shows longer addresses with random letters in them. Those belong to one specific build. Use the short one under Domains.
You should seeWhen you open your website address, the FlowDesk sign-in page. (Don't sign in yet. Do step 8 first.)

No Deploy button, or "No Production Deployment"? Deploy from the dashboard

Vercel only builds your site when you click Deploy or when new code reaches GitHub. If the import screen had no Deploy button, or your project's Overview says No Production Deployment, start the first build yourself:

  1. Open vercel.com/dashboard and click your project.
  2. Go to Settings›Environment Variables. Add the two variables from 7.4 with Production and Preview ticked, and click Save.
  3. Open Deployments and click Create Deployment at the top right (it may be under the ⋯ menu).
  4. Type main as the branch and confirm. Then continue with item 2 of the list above.

If the Deployments list shows an entry marked Blocked, see Troubleshooting.

Seeing "FlowDesk isn't configured yet" instead? One of the two environment variables is missing or misspelled. Go to your Vercel project's Settings›Environment Variables, fix it, then redeploy: open Deployments, click the ⋯ menu on the newest one, and choose Redeploy. Changes to variables only take effect after a redeploy.

7

Install Node.js and start FlowDesk on your computer

10 minutes · one-time install
On my computer path

What is Node.js? Free software that lets your computer run apps like FlowDesk. Visual Studio Code ("VS Code") is a free editor that makes the next steps easy: you'll use it to create one settings file and type two commands.

7.1 Install Node.js and VS Code (once)

  1. Open nodejs.org and download the LTS version (the one recommended for most users). Run the installer and click Next through it, keeping the default options.
  2. Open code.visualstudio.com, download VS Code for your computer and install it with the default options.

7.2 Open the FlowDesk folder in VS Code

  1. Start VS Code. Click File›Open Folder… (Mac: File›Open…).
  2. Go to Documents, click the FlowDesk-Public-main folder that contains package.json (step 1.2), and click Select Folder / Open.
  3. If VS Code asks "Do you trust the authors of the files in this folder?", click Yes, I trust the authors.
You should seeA file list on the left side of VS Code (the Explorer) that includes src, supabase and package.json.

7.3 Create your settings file: .env.local

This small file tells FlowDesk which Supabase project to use. It stays on your computer.

  1. In the Explorer on the left, right-click an empty area below the files and choose New File….
  2. Type the name exactly, including the dot at the start, and press Enter: 
    .env.local
  3. The new, empty file opens. Copy the two lines below and paste them into it: 
    VITE_SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
VITE_SUPABASE_ANON_KEY=paste_your_publishable_key_here
  4. Replace paste_your_publishable_key_here with your publishable key from step 6 (sb_publishable_…). If the first line still shows YOUR-PROJECT-REF, replace that with your project ref too.
  5. Save the file: Ctrl+S (Mac: ⌘+S).
Common mistakes to avoid
  • No quotation marks and no spaces around the =.
  • The file name must be exactly .env.local, in the same folder as package.json, not inside src.
  • Use the publishable (or anon) key, never the secret key.

7.4 Open the terminal inside VS Code

A terminal is a panel where you type commands. You'll type two.

  1. Click Terminal›New Terminal in the menu at the top. A panel opens at the bottom of VS Code, already inside your FlowDesk folder.
  2. Windows only: in the terminal panel's top-right corner, click the small ˅ next to + and choose Command Prompt. (This avoids a Windows security setting that can block the next commands in PowerShell.)
  3. Check that Node.js is installed: type this and press Enter. It should print a version such as v22.12.0 (20 or higher is fine). 
    node -v
    Seeing "node is not recognized" or "command not found"? Close VS Code completely, open it again, and retry. If it still fails, reinstall Node.js (7.1).

7.5 Install and start FlowDesk

  1. Install FlowDesk's building blocks. This downloads them from the internet and takes one to three minutes. Yellow warnings are normal. 
    npm install
    You only need to do this once (and again after updating FlowDesk).
  2. Start FlowDesk: 
    npm run dev
  3. After a few seconds the terminal shows a line like ➜ Local: http://localhost:5173/. Open http://localhost:5173 in your browser. (If it shows a different number, such as 5174, use that address instead.)
You should seeThe FlowDesk sign-in page in your browser. (Don't sign in yet. Do step 8 first.)
Keep the terminal open FlowDesk runs only while npm run dev is running. Closing VS Code or the terminal, or pressing Ctrl+C in it, stops FlowDesk. Step 11 shows how to start it again next time.
Seeing "FlowDesk isn't configured yet"? Something in .env.local is missing or misspelled; the screen tells you which value. Fix the file and save it, then restart: click the terminal, press Ctrl+C, and run npm run dev again. FlowDesk only reads .env.local when it starts.

Set up your workspace and invite your team

15 minutes · inside FlowDesk · use a computer, not a phone

Everything below is in the Admin Panel, at the bottom of FlowDesk's left menu. Do it in this order, because each part is used by the next.

10.1 Branches

A branch is a location, office or customer site that tickets belong to.

  1. Admin Panel›Branches › Add Branch.
  2. Branch ID: a short code such as HQ (can't be changed later). Branch Name: for example Headquarters.
  3. Click Create Branch.

10.2 Products

What your tickets are about: an app, a service, a product line.

  1. Admin Panel›Products › Add Product.
  2. Enter a Name, an optional description, pick a color, and click Create Product.

10.3 SLA targets and approval gates

  • Admin Panel›SLA: how many hours your team has to respond to and resolve tickets of each priority. The defaults are sensible. Edit with the pencil icon.
  • Admin Panel›Gates: status changes that need an approval first. Three are set up for you. Keep them, change them or switch them off.

10.4 Invite your team

There is no sign-up page. You create every account yourself.

  1. Admin Panel›Users › Invite User.
  2. Fill in their Email, Full Name (needed for @mentions), optional company and Branch, and pick a System Role:
    RoleFor
    AdminPeople who run FlowDesk: users, settings, reports.
    DeveloperPeople who work on tickets, log time and ship releases.
    Support deskPeople who sort incoming requests and reply to requesters.
    Branch managerPeople who submit and follow requests for one branch. Needs a branch.
  3. Click Create User. A temporary password is shown only once. Click Copy Password before clicking Done.
  4. FlowDesk doesn't send emails. Send the person your website address, their email and the temporary password yourself, securely (for example via a password manager, or tell them in person). At their first sign-in they choose their own password, just like you did.
Always create people with Invite User in FlowDesk, not with "Add user" in the Supabase dashboard. Accounts made in Supabase start switched off and show "Account Deactivated".
On my computer: who can reach it? Only people using this computer can open http://localhost:5173. You can still create accounts now.   1. Invite yourself with your own email and the Admin role.
  2. Sign out, sign in as your new admin and set your password.
  3. In Admin Panel›Users, deactivate (ban icon) or delete admin@flowdesk.com.

11

Keeping FlowDesk running and up to date

Read once · come back when you need it

If FlowDesk suddenly stops working

The most common reason is that the free Supabase project was paused after a week without use. Open supabase.com/dashboard, open your project, and click Resume project / Restore. It's back in a few minutes.

On my computer

Starting FlowDesk again next time

FlowDesk stops when you close VS Code or restart your computer. Your data is safe in Supabase. To start it again:

  1. Open VS Code. It usually reopens your FlowDesk folder; if not, use File›Open Folder… as in step 7.2.
  2. Open Terminal›New Terminal (on Windows, switch it to Command Prompt as in step 7.4).
  3. Run the command below, then open http://localhost:5173. 
    npm run dev

To stop it, click the terminal and press Ctrl+C, or just close VS Code.

Getting updates

  1. Download the new ZIP from the FlowDesk repository and unzip it into Documents, as in step 1. (Used git clone? Run git pull instead, then skip to step 3.)
  2. Copy your .env.local file from the old folder into the new one. (It starts with a dot, so on a Mac press ⌘+Shift+. in Finder to see it. In VS Code it's always visible.)
  3. Open the new folder in VS Code and run npm install, then npm run dev.
  4. Check whether the update changed the database or the Edge Function: read CHANGELOG.md, and look in supabase/migrations/ for new files. Run only the new SQL files in the SQL Editor, oldest first, as in step 3. If supabase/functions/admin-actions/index.ts changed, replace the function's code in Edge Functions, redeploy it, and check that Verify JWT is still off (step 4.3).

Changing a setting

Edit .env.local in VS Code and save it, then restart FlowDesk: press Ctrl+C in the terminal and run npm run dev again.

Ready to share it with your team?

Move to the online path whenever you like. See Appendix A.

Online

Getting updates from the original FlowDesk project

  1. Open your fork on GitHub. If there are updates, you'll see "This branch is X commits behind".
  2. Click Sync fork › Update branch.
  3. Vercel notices the change and rebuilds your website automatically within a few minutes.
  4. Check whether the update changed the database or the Edge Function. Vercel only updates the website, not Supabase. Read CHANGELOG.md in your fork, and look in supabase/migrations/ for new files:
    • New SQL file(s)? Run only the new ones in the SQL Editor, oldest first (the file names start with a date), exactly as in step 3.
    • Changed supabase/functions/admin-actions/index.ts? Open the function in Edge Functions, replace its code with the new file, redeploy, and re-check that Verify JWT is still off (step 4.3).

Changing an environment variable later

  1. In Vercel, open your project › Settings›Environment Variables, edit the value and click Save.
  2. Open Deployments, click ⋯ on the newest deployment, and choose Redeploy. The change doesn't apply until you do.

Using your own domain (optional)

  1. In Vercel: your project › Settings›Domains › Add Domain. Enter it (for example help.yourcompany.com) and follow the DNS instructions Vercel shows, at the company where you bought the domain.
  2. In Supabase: Authentication›URL Configuration. Set Site URL to the new domain and add https://help.yourcompany.com/** to Redirect URLs.

A

Appendix A: Switch paths, or use both

Both paths share one Supabase database, so nothing is lost

Your data (users, tickets, settings) is stored in Supabase, not in Vercel or on your computer. That means you can move between the two paths, or use both at once, without redoing steps 2 to 6 and without losing anything.

From "On my computer" to "Online"

For when you're ready to let your team in:

  1. Do online step 1: create a GitHub account and fork FlowDesk.
  2. Do online step 7: deploy on Vercel with the same two values that are in your .env.local.
  3. Do online step 8: set the Site URL to your Vercel address, and keep http://localhost:5173/** in Redirect URLs if you'll still run it locally.
  4. Sign in at your Vercel address with the admin password you already chose. Then invite your team (step 10.4).

From "Online" to also running it on your computer

Handy for trying changes privately before they go live:

  1. Do local step 7 on your computer. For the code, either download the ZIP (local step 1) or clone your fork: git clone https://github.com/YOUR-USERNAME/FlowDesk-Public.git.
  2. Add http://localhost:5173/** to Supabase's Redirect URLs (local step 8). Leave the Site URL set to your Vercel address.
Both copies use the same data. Anything you change while running locally (tickets, users, settings) is immediately visible on your live site.

Use the path switcher at the top of the contents list to see either path's full steps at any time.

B

Appendix B: Steps 3 and 4 from the command line (optional)

An alternative for people comfortable with a terminal

Instead of pasting into the dashboard, you can build the database and deploy the function with the Supabase command-line tool. You need Node.js and the code on your computer, as in the On my computer path's step 1 and steps 7.1 to 7.4. Run these in the VS Code terminal, inside the FlowDesk folder. The first time, answer y if asked to install supabase.

Sign in (press Enter, approve in the browser, then paste the verification code it shows)
npx supabase login
Connect this folder to your project (asks for the database password from step 2)
npx supabase link --project-ref YOUR-PROJECT-REF

A WARNING: Local config differs from linked project message after link is expected and harmless: the repository's supabase/config.toml is for running Supabase on your own computer. There is nothing to run.

Run both database scripts, in order (replaces step 3)
npx supabase db push
Deploy the Edge Function with JWT verification off (replaces 4.1 to 4.3)
npx supabase functions deploy admin-actions --no-verify-jwt

Then do the check in step 4.4 and carry on with step 5. Later updates are the same: npx supabase db push applies only new database files.

C

Appendix C: Locked out? Reset the admin account

In the Supabase SQL Editor

If you forget the admin password, or every admin gets deactivated, open the SQL Editor in Supabase, start a new query, paste the following and click Run. It sets admin@flowdesk.com back to the starter password Password2026!, switches it on, makes it an admin, and asks for a new password at the next sign-in.

Open a new SQL query

UPDATE auth.users
   SET encrypted_password = extensions.crypt('Password2026!', extensions.gen_salt('bf')),
       updated_at = now()
 WHERE email = 'admin@flowdesk.com';

UPDATE public.profiles
   SET role = 'admin', is_active = true, force_password_reset = true
 WHERE email = 'admin@flowdesk.com';

For a different person, replace admin@flowdesk.com (both places) with their email, and Password2026! with a temporary password of your own.

Glossary: plain-English meanings

Repository (repo)
A project folder on GitHub that holds all of a project's files and their history.
Fork
Your own copy of someone else's repository, in your GitHub account. You can change it without affecting the original, and pull in the original's updates with "Sync fork".
Clone
Downloading a repository to your computer with Git, so it stays connected to GitHub.
Branch (main)
A line of work inside a repository. main is the official version, the one Vercel publishes. (Not the same as a FlowDesk "branch", which is a location.)
Deploy
Publishing code so it runs online. Vercel deploys the website; you deploy the Edge Function to Supabase.
Project ref
The 20-character ID of your Supabase project, found in its web address.
SQL / SQL Editor
SQL is the language databases understand. The SQL Editor is the page in Supabase where you paste and run SQL scripts.
Migration
A SQL script that builds or changes the database. FlowDesk's live in supabase/migrations/ and run oldest first.
Edge Function
A small program that runs on Supabase's servers. FlowDesk's is called admin-actions.
JWT
The digital "ticket" that proves who is signed in. FlowDesk's Edge Function checks it itself, which is why Supabase's own check is switched off.
Environment variable
A named setting (like VITE_SUPABASE_URL) given to the website when it's built, instead of being written into the code.
Publishable key / anon key
A public Supabase key that's safe to put in a website. The database's security rules decide what it can do.
Secret key / service_role key
A private Supabase key with full access. Never put it in the website or in Vercel.
Redirect URL / Site URL
Web addresses Supabase is allowed to send people back to after signing in. They should be your website's address.
Terminal
A panel or window for typing commands. In this guide you use the one built into VS Code. Only needed on the On my computer path and in Appendix B.
localhost
Your browser's name for "this computer". http://localhost:5173 is FlowDesk running on your own machine; other people can't open it.
Node.js / npm
Node.js is free software that runs apps like FlowDesk on your computer. npm comes with it: npm install downloads FlowDesk's building blocks and npm run dev starts FlowDesk.
.env.local
The settings file for running FlowDesk on your computer. It holds the same two values you'd give Vercel, and is never uploaded anywhere.
